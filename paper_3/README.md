# Work 3: hidden-state wastewater control

Code for the shared diffusion model, data collection and training, seven benchmark controllers, belief correction, forecast selection, oxygen preference, and disturbance monitoring. Models, inflow records, trajectory datasets and experiment outputs are not included.

## Install

Use Python 3.11. Run these commands from `paper_3/` in a separate virtual environment:

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python reproduce.py list
```

Training and calibration require CUDA. Evaluation defaults to CUDA; `--device cpu` is available for evaluation. The pinned PyTorch version is 2.8.0, tested with CUDA 12.8.

## Inputs

Place the official BSM1 dry, rain and storm influent records in `inputs/forcing/` as `Inf_dry_2006.txt`, `Inf_rain_2006.txt` and `Inf_strm_2006.txt`. These are external physical forcing records, not generated by the training-data collector. Each must have the header `t SI SS XI XS XBH XBA XP SO SNO SNH SND XND SALK Q` and the official 15-column values. `simulator/inputs.py` validates and converts this layout.

`configs/inputs.json` records expected paths and reference hashes. Set `WORK3_INPUTS` to use a different input directory. No code searches another project for missing inputs. Generated files remain under ignored `inputs/` or `outputs/` directories.

## Create training data and models

Given the three official inflow files, collect the physical episodes, combine the behavior policies and freeze the training, validation and calibration splits:

```bash
python prepare_data.py collect-original --root outputs
python prepare_data.py prepare-shared --root outputs
python prepare_data.py collect-shared --root outputs
python prepare_data.py freeze --root outputs
```

Use `--workers N` to set the collection worker count. Collection creates complete forcing families; the freeze repairs the source split at episode 59 and holds out the three calibration parents. Training uses only the generated training and validation splits.

Fit the width-256 velocity-prediction shared model for 200,000 updates, then continue the same optimizer and random state to 300,000 updates. Fit the two learned baselines separately:

```bash
python -m bsm1_offline_benchmark.joint_diffusion train --data outputs/prepared/data --output outputs/models/joint_diffusion_200k --width 256 --prediction-type v --updates 200000 --batch-size 128 --seed 17
python -m bsm1_offline_benchmark.joint_diffusion train --data outputs/prepared/data --output outputs/models/joint_diffusion_continued --resume outputs/models/joint_diffusion_200k/last.pt --updates 300000 --batch-size 128 --seed 17
python -m bsm1_offline_benchmark.stock_han train --data outputs/prepared/data --output outputs/models/stock_han
python -m bsm1_offline_benchmark.stock_yang train --data outputs/prepared/data --output outputs/models/stock_yang
python prepare_data.py calibrate --root outputs --checkpoint outputs/models/joint_diffusion_continued/last.pt
```

Use the completed continuation's `last.pt` for calibration and evaluation: the final controller requires exactly 300,000 updates. `best.pt` may identify an earlier validation minimum for a new fit. Both files have the same loadable checkpoint schema. Calibration recomputes the evidence-temperature diagnostic; it does not silently change the fixed evaluation parameters. `research_shared_model/defaults.py` defines the final controller recipe, and `configs/detector.json` defines the passive monitor. New fits can differ from the reference checkpoints.

Install the generated checkpoints into the evaluation layout:

```bash
mkdir -p inputs/models
cp outputs/models/joint_diffusion_continued/last.pt inputs/models/joint_diffusion.pt
cp outputs/models/stock_han/final.pt inputs/models/stock_han.pt
cp outputs/models/stock_yang/final.pt inputs/models/stock_yang.pt
```

Alternatively, supply the reference checkpoints directly. For supplied reference training arrays, place `train.npz`, `validation.npz` and `calibration.npz` in `inputs/training/` and copy `configs/training_manifest.json` there as `manifest.json` to run calibration. This compact manifest supplies the calibration case definitions; newly generated data has its own complete manifest.

## Evaluate and summarize

Each full episode has 1,344 fifteen-minute decisions over fourteen days, including startup. `configs/test_cases.json` and `configs/development_cases.json` define the six TEST and three DEV forcing realizations. DEV denotes the prescribed scientific evaluation cohort.

| Study | Evaluation |
|---|---|
| `benchmark` | GenAIF, history-conditioned diffusion, truth-conditioned diffusion, PI, expert PI, Han Koopman and Yang offline RL on six TEST cases |
| `correction` | Paired TEST runs with and without the oxygen/nitrate mean correction |
| `forecast-selection` | Paired TEST runs with forecast ranking or candidate 0 selection |
| `development` | Three final-controller DEV traces for forecast and belief analysis |
| `preference` | Three DEV pairs with oxygen preference weight 0 or 0.01 |
| `settling` | Dry DEV nominal, six-hour, one-day and permanent settling-capacity changes |
| `oxygen-transfer` | Three DEV pairs with nominal or reduced oxygen-transfer effectiveness |
| `sensor-offset` | Dry DEV clean and offset effluent-ammonium observations |

For newly trained models, explicitly permit input hashes that differ from the reference:

```bash
python reproduce.py run benchmark --allow-different-inputs
python reproduce.py run correction --allow-different-inputs
python reproduce.py run forecast-selection --allow-different-inputs
python reproduce.py run development --allow-different-inputs
python reproduce.py run preference --allow-different-inputs
python reproduce.py run settling --allow-different-inputs
python reproduce.py run oxygen-transfer --allow-different-inputs
python reproduce.py run sensor-offset --allow-different-inputs
python report_results.py --root outputs
```

For the reference checkpoints and inflows, run `python reproduce.py verify-inputs` and omit `--allow-different-inputs`. Each run records actual input hashes and whether they match. `--job` selects one identifier from `list`; `--output` selects a fresh output directory. Existing run directories are preserved. `--steps 1` or `--steps 2` performs a short implementation check excluded from scientific summaries.

The runner saves physical arrays, per-decision diagnostics and belief forecasts. `report_results.py` writes `summary.csv`, `paired_effects.json` and `appendix_readouts.json`. `analyze_appendix.py` derives the belief-error, monitor-recovery and saved-candidate preference analyses separately. These commands use generated traces; no published result tables are embedded. Passive monitoring does not alter control actions or train a model.

Export numerical inputs for the repository's figure builders after running the required complete episodes:

```bash
python export_figures.py benchmark --root outputs --output outputs/plot_benchmark
python export_figures.py forecast --root outputs --output outputs/plot_forecast
python export_figures.py belief --root outputs --output outputs/plot_belief
```

The first two exports require all benchmark or forecast-selection cases, respectively. The belief export uses the storm DEV final-controller run and preserves its first nine recorded boundaries. Use `all` with a fresh output directory to export all three sets together. Plot commands are documented in `../reproduction/figures/README.md`.
